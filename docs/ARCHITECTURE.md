# 产品与架构方案（已确认；首版实现）

## 技术选择

**已选 Electron + TypeScript + 本地 Node 任务进程。** Pi SDK 原生运行于 Node/Bun；Electron 复用类型与事件协议。这里的“后端”随应用打包，不开放网络端口，也不预设云端账号服务。点击一键部署后初始化 SQLite 并启动；重启会中断正在运行的任务，并在恢复后标记为失败。

```text
Electron renderer（无 Node、仅展示）
  └─ 限定的 preload IPC
      └─ main（项目注册、审批、调度、持久化）
          ├─ SQLite（项目、任务、事件、策略、草稿、计划）
          ├─ Git 只读采集器（commit、diff、路径证据）
          └─ 每任务独立 Pi worker（session、model、skills、events）
```

主进程控制后端生命周期与 IPC，渲染进程启用隔离与沙盒，不直接拿文件系统或 API key。写作与事实审校是两个独立 Pi 会话，作为子任务在 SQLite 中记录角色、Provider、模型、状态及输出；按依赖顺序运行，尚不支持任意并行委派。Git 证据采集由宿主执行，不是第三个模型 Agent。自定义 OpenAI 兼容中转商的配置单独保存，凭据保存在 Pi `auth.json`，模型可手工指定或明确请求 `/models`；内置列表来自 Pi 模型目录而非实时远端。`OPS_` 环境配置以 `0600` 存储，只有 `OPS_IMAGE_` 传给内嵌 Responses 生图模块，普通 Pi 任务与第三方 Skill 脚本无执行权限。发布仍由人决策。

## 数据与工作流

`Project` 记录规范化的本地 Git 路径、远端标识和允许公开范围；`Run` 固定起止 SHA、启动时脏工作树状态、模型/Skill 版本及策略版本。`Evidence` 保存主张→SHA/文件/行/发布状态；`Artifact` 保存草稿、标题、封面 brief 和审阅版本。`Event` 是应用级追加式审计：工具动作、时间、审批者、决定和结果，敏感参数脱敏。Pi JSONL 会话用于恢复对话，**不能代替**审批与事实账本。

采集 → 风险筛查 → 事实卡 → 选题 → 草稿/标题/封面 brief → 独立核对 → 人工审批/编辑 → 手动发布 → 手动录入链接和反馈 → 策略复盘。不同项目的提交、记忆、凭据与 Skill 启用范围不可串用。运营策略是可编辑、可版本化的记忆；产品事实只以选定 Git 基线及明确补充的人工证据为准。

Pi 接入建议按项目 `cwd` 创建 `createAgentSession`，由 `ModelRuntime` 管理提供商与模型、`SessionManager` 持久化对话、`DefaultResourceLoader` 装载受信 Skill；订阅工具和消息事件写入审计。使用 `steer()` 追加纠偏，`abort()` 中止运行；`steer()` 不是立即撤销已执行的工具操作。默认只开放读取工具；写仓库、外部网络、运行脚本、安装 Skill、清理文件都需单独的宿主审批。用户现有脏改动不可自动重置或清理；需要写代码时优先独立 worktree 并展示 diff。

## 页面与状态

1. **项目总览**：多仓库、最新 SHA、待处理提交、Git 脏状态、计划和活跃任务。
2. **任务编排**：阶段图、角色/Provider/模型/Skill、输入基线、重试、人工闸门。
3. **执行与纠偏**：实时事件、工具输入输出（脱敏）、证据和 diff、暂停审批、纠偏、终止、重跑、审阅；清楚区分“已排队纠偏”与“已停止”。
4. **内容工作台**：事实卡、选题池、草稿、标题、图片 brief、来源对照、版本与发布状态。
5. **计划与记忆**：时区、错过任务策略、并发锁、下次执行；策略/反馈/会话分区查看与纠正。
6. **设置**：Provider 认证与连通测试、Skill 来源/启用范围、保留期预览与清理、导出与恢复。

空状态引导添加 Git 仓库；失败状态保留原因与重试入口。首版定时任务只保证**应用运行期间**执行；错过的触发在重开应用后最多补跑一次。退出后运行需要另设计系统 helper。历史清理先预览，只清理到期的已发布产物、已结束任务事件和旧会话/图片文件，不清除 Git 仓库、项目记忆和未发布草稿。导出与恢复尚未实现。

## 交付阶段

1. 纵向样机：两个仓库、Pi 多 Provider 会话、提交证据卡、草稿、任务事件、人工审批与纠偏。
2. 完整运营闭环：Skill 导入/开发、策略记忆、定时生成、图像与润色、反馈复盘。
3. 打包与强化：macOS/Windows 构建、签名、迁移、备份、后台运行（如确认需要）、安全测试。
